## Answer

**Cause:** a column‑name mismatch. Your code reads the key `qty_on_hand`, but the CSV header is `qty_onhand` (no underscore between *on* and *hand*). `csv.DictReader` builds each row dict from the header, so `row["qty_on_hand"]` doesn't exist → `KeyError`.

**Fix (line 57 of `stock_sync.py`):**

```python
qty = int(row["qty_onhand"])
```

That's the minimal change to stop the crash.

**Two things to double‑check:**

1. **Other references.** Grep the file for the same wrong name so you don't just hit the next crash:
   ```bash
   grep -n "qty_on_hand" stock_sync.py
   ```
   Update every occurrence to `qty_onhand` (or, if you'd rather keep the code as‑is, rename the column in the CSV header to `qty_on_hand` — but since this file is an *export* from another system, fixing the code to match the export is usually the safer direction).

2. **Whitespace/encoding.** If after the rename you still get a `KeyError`, the header cell may contain a BOM or trailing space. You can guard against that by stripping keys when reading, e.g. `{k.strip(): v for k, v in row.items()}`, but the screenshot shows a clean header, so the plain rename should be enough.
